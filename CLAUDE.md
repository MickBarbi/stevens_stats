## What this project is

**Stevens Stats** — a static Next.js (App Router, TS) site tracking a college
track & field team's results, for fans following teammates (often without
knowing the events). See `README.md` for the full picture.

- **Fully static.** No API routes, no database. Every route is prerendered at
  build from `data/*.json`, imported via `lib/data.ts`.
- `data/athletes.json` / `events.json` / `performances.json` are regenerated by
  the Python scraper — `scraper/README.md`.
- `data/qualifying_standards.json` / `blog_posts.json` are hand-maintained —
  `data/README.md`.
- A "career best" is a `performances.json` row with an `is_*_best` flag (no
  separate bests table).
- Mark display: `lib/format.ts`. Photos: `lib/photo.ts` (Cloudinary,
  public_id = TFRRS id).
- Old DB/Prisma API routes are parked in `archive/` (excluded from the build);
  `prisma/schema.prisma` is kept as a data-model reference only.
- Deploys on Vercel as static, $0. Refresh: `npm run data` → commit
  `data/*.json` → push.

## Active work

**`docs/REDESIGN.md`** is the live plan + progress tracker for the current
effort (making the site look/feel great, fixing dark mode & mobile). It has the
vision, the diagnosis, a tiered checklist, and a progress log. Update it as work
lands.

## Working agreements

- Verify with `npx next build` (static export of all routes) before considering
  UI work done; `npx tsc --noEmit` and `npx next lint` should be clean.
- Commit straight to `master` in small, themed commits with detailed messages.
- Don't reintroduce a database or API routes without the user asking.
